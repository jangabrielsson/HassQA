# HassQA project review — 2026-11-17

Reviewed at v0.75.1 (commit `07656d0`). Scope: all shipped Lua files
([HASS.lua](../HASS.lua), [Classes.lua](../Classes.lua), [Utils.lua](../Utils.lua),
[Config.lua](../Config.lua), [User.lua](../User.lua),
[HASSConnector.lua](../HASSConnector.lua)), the release artifact
([HassQA.fqa](../HassQA.fqa)), and the release/process setup.

**Overall:** a well-structured integration — the Entity/subscriber model, the class
registry with `auto`/`customTypes`, and the clean release pipeline (placeholders
verified in the packed fqa, `.version`/`VERSION` in sync, `flua --check` passes) are
all solid. But there are a few real bugs, several robustness gaps around the
websocket lifecycle, and a fair amount of dead/unfinished code.

---

## 🔴 High-impact bugs

1. ✅ **Fixed 2026-11-17** (in-place entity resync + reconnect guard in
   `QuickApp:authenticated`; regression test in `dev/test_reconnect.lua`).
   **Reconnect silently kills all child updates.** Every reconnect re-runs
   `QuickApp:authenticated()` (auth_required → auth_ok → `authenticated()`), which
   does `entities[e.entity_id] = Entity(e)` unconditionally — replacing every Entity
   with a fresh one that has an **empty `subscribers` table**. Existing children
   (which subscribe once in `HASSChild:_addEntity`) stay subscribed to the orphaned
   old objects, so after a HASS restart or network blip no child QA receives updates
   until a manual restart. Fix: on re-auth, update existing Entity objects in place
   (or carry subscribers over), or simply `plugin.restart()` on reconnect.

2. **`QuickApp:log` timer bug.** `QuickApp:log` (HASS.lua ~line 223) assigns
   `logTimer = self:updateView(...)` (not a timer ref) and never captures the
   `setTimeout` return. `clearTimeout(logTimer)` clears garbage, and overlapping log
   calls blank the label early. Should be `logTimer = setTimeout(...)`.

3. **`Fan` is broken.** `Fan:logState` (Classes.lua ~line 748) references the
   undefined global `d` (`d.state`) and is called from every `Fan:update` → every
   fan state change throws (swallowed by the subscriber pcall, so the fan simply
   never updates).

4. ✅ **Fixed 2026-11-17** (`new_state == nil` guard in `MessageHandler.event`:
   subscribers are notified with `unavailable`, then the entity is dropped;
   regression test in `dev/test_events.lua`).
   **Removed-entity events crash the handler.** In `MessageHandler.event`
   (HASS.lua ~line 70), when HASS deletes an entity the event has
   `new_state = null`. For a known entity, `entity:change(nil)` indexes nil
   (`e.state`) — and this path is *not* pcall-protected (only request callbacks are,
   in `handleDataReceived`). For unknown entities, `pcall(Entity, nil)` fails and
   logs an error on every such event. Guard `data.new_state == nil` →
   unsubscribe/remove the entity.

5. ✅ **Fixed 2026-11-17** (late-entity branch now checks `entityFilter:skip`
   and records skipped ids; regression test in `dev/test_events.lua`).
   **Late entities bypass the filter.** The late-entity branch
   (HASS.lua ~line 81) creates the Entity without consulting `entityFilter:skip` —
   entities excluded at startup (e.g. `update.*`, `fibaro_id` mirrors) get re-added
   if they appear after startup, which on a Fibaro↔HASS loop reintroduces the echo
   problem the filter exists to prevent.

6. **`Thermostat:__init` crashes when no climate entity resolves.**
   (Classes.lua ~line 816) does `self.mainId.attributes` with no nil-check on
   `firstEntityType('climate_hvac')`.

## 🟠 Robustness weaknesses

7. ✅ **Fixed 2026-11-17** (pong deadline: a ping without a pong within 10 s
   triggers `WSConnection:reconnect`, which closes the socket and dials a fresh
   one; the disconnect path uses the same guarded reconnect. Note: the original
   claim that "pinging stops" was inaccurate — pings kept being sent, but
   nothing ever *checked* for pongs, which is what the fix adds. Regression
   test in `dev/test_pong.lua`.)
   **No dead-connection detection.** The keepalive in `WSConnection:ping`
   (Utils.lua ~line 66) only reschedules the next ping *when the pong arrives*. If
   the connection goes half-open, the pong never comes, pinging stops, and the QA
   waits forever for a `disconnected` event that may never fire. Add a pong-timeout
   that forces a reconnect.

8. **Silent 5-second callback drop.** `WSConnection:send` (Utils.lua ~line 79)
   deletes the callback after 5 s with no error path. Worst case: the `get_states`
   reply during startup takes >5 s on a big HASS install → `self._initialized` is
   never set, no children load, no retry, no error. At minimum call
   `cb(nil, "timeout")` and retry the startup fetch.

9. **`mainId` type confusion.** The base class sets `self.mainId = entity_ids[1]`
   (a *string*), subclasses set it to the result of `firstEntityType(...)` (an
   *Entity object*, possibly nil), and `update()` reassigns it to the event entity.
   `send()` requires an object (`entity.domain`, `entity.id`). A `turnOn` arriving
   before the first state update can hit the string/nil case. Also note
   `DimLight:__init`'s `firstEntityType('light')` is usually nil because
   `customTypes` remaps dimmable lights to `light_dim`/`light_rgb`. Pick one
   representation (the Entity object) and resolve it once.

10. **`rooms` snapshot at load time.** (HASS.lua ~line 395) fetches `/rooms` once
    at file load; rooms created later are reported as "not found" until restart.
    Fetch inside `newChildQA`.

11. **DST bug in `os.utc2time`.** (Utils.lua ~line 160) computes `zone_diff` once
    with `isdst=false`; button-event timestamps will be off by an hour part of the
    year. This matters because `Button:update` (Classes.lua ~line 498) discards
    events older than 1 s — a DST shift makes all button presses "old" and silently
    ignored.

12. **nil-value property updates.** `Humidity:update` (Classes.lua ~line 700) does
    `tonumber(entity.state)` with no `or 0` fallback — states like `"unknown"` push
    `nil` to `updateProperty`. Most siblings handle it; make it consistent.

13. **HC3 API write amplification.** `DEBUGF` (Utils.lua ~line 11) calls
    `quickApp:log()` → `updateView` for *every* debug line, and the shipped default
    enables eight debug channels
    (`--%%var:debug="main,wsc,child,color,battery,speaker,send,late"`). Similarly
    `Zone:logState` (Classes.lua ~line 924) calls `setVariable` for every person on
    every zone update. Consider shipping with `debug=""` and throttling
    view/variable writes.

## 🟡 Dead and unfinished code

- **[HASSConnector.lua](../HASSConnector.lua) is a near-verbatim duplicate of
  `WSConnection`** in Utils.lua and isn't in the `--%%file:` list — it never ships
  and will drift. Delete it or make it the single source.
- The 70-line `climate` JSON test fixture (HASS.lua ~line 141) is decoded on every
  startup and never used.
- The **"Dump config" UI button is a no-op** (`dumpConfig` just logs
  "Dumping config").
- Leftover `print(className)` in `loadAuto` (HASS.lua ~line 240); duplicate
  `local n = 0` counters in HASS.lua (the second shadows `newUID`'s and is dead);
  `math.round` defined twice (Utils + Classes); `string.buff().tostring()` computes
  an HTML-escaped `str2` and then returns `str` — the gsub work is dead.
- Known-incomplete: `XYLight:setColor` ("ToDo convert xy to rgb"), `Lux.toLux`
  (flagged "This is not right!" — HASS illuminance sensors report lux directly in
  `entity.state`, so the log-curve conversion of `light_level` is doubly wrong),
  `TV:sendAVControl`.
- Small ones: `WARNINGF(...entity...)` in `_addEntity` (Classes.lua ~line 285) uses
  undefined `entity` instead of `entity_id`; `color()` (Utils.lua ~line 6) leaks the
  global `str` (missing `local`); `RGBLight:setColor` sends a 4-element `rgb_color`
  (HASS expects 3; 4 values is `rgbw_color`); typo "put you HASS api token here".

## 🔒 Security

- Credentials handling in the release artifact is **good** — placeholders only,
  verified in [HassQA.fqa](../HassQA.fqa).
- The websocket URL is hardcoded `ws://` (Utils.lua ~line 60); there's no way to
  reach a TLS-fronted HASS (`wss://`, e.g. Nabu Casa or reverse-proxied installs).
  Accept a full URL or a scheme toggle.

## 🧰 Process / maintainability

- **No tests.** [AGENTS.md](../AGENTS.md) prescribes the flua-test loop, but the
  repo contains no test QA. Most of the bugs above (reconnect, removed entities,
  Fan, log timer) are exactly the kind an offline test QA with a mocked
  `WSConnection`/injected events would catch. A `dev/test_hass.lua` that stubs
  `net.WebSocketClient` and replays a recorded `get_states` + `state_changed`
  stream would pay for itself immediately.
- **No CI** — even a workflow running `flua --check` + a test QA + a
  pack-and-verify step (the AGENTS.md fqa check) on push would protect releases.
- [README.md](../README.md) is one line (a forum link). Fine for users, but a short
  "install, set url/token, class/auto concepts, how `Config.lua`/`User.lua`
  customization works" section would help contributors; most of that prose
  currently lives only in code comments.
- `Config.lua` and `User.lua` mix shipped defaults with user examples inside the
  packaged QA — consider clearly marking User.lua as "safe to edit, survives
  updates" vs. not, since `updateQA` file-sync behavior determines whether user
  edits get clobbered on upgrade.

## Suggested priority

1. **Fix the reconnect/resubscribe bug (#1)** — it defeats the auto-reconnect
   entirely.
2. **Harden the event handler (#4, #5) and add a pong-timeout (#7).**
3. **Fix the small certain bugs** (#2 log timer, #3 Fan, #6 Thermostat init,
   `_addEntity` warning variable, `color()` global leak).
4. **Add an offline test QA + CI check** to lock it all in.
5. **Sweep the dead code** (HASSConnector.lua, climate fixture, no-op Dump-config
   button, leftover prints).
